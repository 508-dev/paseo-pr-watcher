PR watcher keeps a selected Paseo agent aware of its GitHub pull request after the agent finishes. Open **Watch PR** from a workspace header or agent tab, pick the PR detected from its current branch, and choose the agent that receives follow-ups. The agent-tab control preselects that agent, and the workspace header defaults to the focused agent when one is available. Multiple matches use a picker, and a manual URL field handles PRs that discovery cannot find. On compact layouts the header control lives in the workspace menu.

The control becomes **Watching #123** and opens watch status, last check, follow-up counts, and a stop action. Paused and uncertain watches show their recovery state. The Command Center watch list and `/watch-pr owner/repo#123` shortcut remain available. Switching branches does not retarget an existing watch.

The daemon machine needs Node and npm for Git preparation, and the GitHub CLI (`gh`) installed and authenticated with access to the watched repositories. Preparation installs locked SDK and validation dependencies with lifecycle scripts disabled. Watching is opt-in per PR. The plugin reads PR status, checks, and reviews through `gh pr view`; it sends the relevant events to the selected Paseo agent. It stores watch state on the daemon machine at `$PASEO_HOME/plugins/pr-watcher-state.json`, or at `~/.paseo/plugins/pr-watcher-state.json` when `PASEO_HOME` is unset. Set `PASEO_PR_WATCHER_STATE_FILE` to use another location.

Existing failures and reviews form the initial baseline. The plugin wakes the agent only for later changes. It waits at least ten minutes between follow-ups and pauses after five. If delivery is uncertain, it stops automatic sends and asks you to inspect the chat before retrying or marking the event handled. A closed PR stops its watch. The plugin requires Paseo 0.16.0 beta 1 or newer within the 0.16 series, including a compatible app client.
